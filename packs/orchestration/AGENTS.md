# Orchestration

- When I agree to a **side fix**, an unrelated fix in its own pull request, my yes is also my request for its new thread. Hand it off as the T3 guide says, and keep this thread on its own task.
- When a request needs more than one stack of pull requests or several days of work, propose a map. After I agree, run the `orchestration-wayfinder` skill. Maps live in the issues of the repo in `orchestration.tracker`. When that setting is not set, they live in the GitHub repo of the profile directory named in `~/.config/fleet/machine.json`, which must have issues turned on.
- Ask each round of the `grilling` skill with your harness's question tool when it has one: `AskUserQuestion` in Claude Code, `request_user_input` in Codex. Give each question its own entry: a short form of its title as the header, its body as the question, your recommendation as the first option marked "(Recommended)", and the other choices after it. I type any other answer in the tool's free-text field. When a round has more questions than one call takes, ask the rest in more calls in the same turn. Make the round's other tool calls first, such as a park comment or a notice. Without a question tool, the round is your final message.
