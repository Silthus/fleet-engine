# T3 threads and machines

## New threads

A new T3 thread is for separate work that I act on: a coding session, a prototyping session, or a side fix. To call the other provider, Claude to Codex or back, delegate through T3 Code as a subagent or a new thread.

Hand a side fix to a new top-level thread with `t3_thread_launch` and a new worktree from the default branch on origin. The launch message carries the problem, the evidence, and the thread and task it came from, and asks the new thread to open the pull request and link it to itself. Then keep this thread on its own task.

## Other machines

My Mac and my devboxes are linked in T3. To start a thread on another machine, call `t3_thread_launch` with its `environmentId` from `t3_environment_links` and a `projectId` from `t3_project_list` there. `delegate_task` takes the same id in `target.environmentId`. Thread ids belong to their machine, so pass the `environmentId` with every call about a thread there.

## Switch a thread's model

Interrupt the thread (`t3_thread_interrupt`), set the model (`t3_thread_configure`), and resend its last user message (`t3_thread_send`). The thread keeps its context.

## Usage limits

A thread that hits a usage limit waits and resumes by itself when the limit resets. Do not restart it by hand.
